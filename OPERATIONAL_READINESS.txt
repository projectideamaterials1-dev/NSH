CRIMSON NEBULA — OPERATIONAL READINESS TRACKER
================================================
Scope: this is a simulation / decision-support platform. It does NOT command real
spacecraft (see README) - burns are simulated only. This file tracks two separate
tracks: (A) hardening it as a trustworthy ops/decision-support tool, and (B) what
would additionally be required to ever command a real spacecraft.

DONE
----
[Security]
- Role-scoped API-key auth (API_KEYS_OPERATOR / API_KEYS_READONLY), constant-time
  compare, per-request actor attribution (middleware/auth.py)
- Per-IP sliding-window rate limiting on /api/* (RATE_LIMIT_PER_MINUTE)
- Trusted-proxy-aware client IP resolution (X-Forwarded-For only trusted from
  configured proxy IPs)
- TLS termination via nginx on :443 by default, :80 redirects to :443
  (nginx.conf); scripts/generate-dev-cert.sh for local/staging self-signed certs
- Docker image rebuilt as non-root: 3-stage build, compiler/dev headers never
  reach the runtime image, runs as uid 1000 (acm) (Dockerfile)
- Redis now requires a password (REDIS_PASSWORD, compose fails fast if unset),
  wired into both the redis service and the backend's REDIS_URL
  (docker-compose.prod.yml)
- .env.example added documenting every compose variable; certs/ and .env gitignored

[Reliability]
- Redis-backed durable state manager with leader election across replicas
  (state_redis.py) + LeaderGateMiddleware rejects mutations on non-leader replicas
- Async SQLite mission archive (db.py): maneuvers + events survive restarts,
  crash-orphaned pending maneuvers detected and flagged on startup for review
- REQUIRE_DURABLE_STATE=1 option to refuse startup rather than silently run
  in-memory-only if Redis is unreachable

[Testing / CI]
- pytest suite with 80% coverage gate blocking merges
- Dedicated fault-injection, property-based, and screening-latency benchmark
  test suites (tests/integration/test_fault_injection.py,
  tests/unit/test_properties.py, tests/benchmark/)
- Frontend unit tests (Vitest) + Playwright e2e in CI
- CI builds and pushes a versioned Docker image to GHCR on tagged releases
